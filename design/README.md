# 경희대 키우기 디자인 export

Claude Design 캔버스("경희대 키우기 민원인·직원 웹앱")의 화면 코드와 이미지를 그대로 꺼낸 패키지입니다.
개발 레포의 `design/` 폴더에 통째로 넣고, Claude Code에게 "design 폴더를 기준으로 구현해줘"라고 하면 됩니다.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `design/*.dc.html` | 화면별 디자인 코드 (7개) |
| `design/canvas.json` | 캔버스 배치·화면 제목 |
| `assets/` | 지도, 마스코트, 꾸미기 전후 이미지 |
| `assets/fonts/` | 픽셀 한글 폰트 갈무리11 (OFL 라이선스, 상업·비상업 무료) |

## 화면 목록과 흐름

| 파일 | 화면 | 담당 |
|---|---|---|
| `Login.dc.html` | 공통 로그인, 민원인/직원 역할 분기 | 공통 |
| `Main.dc.html` | 민원인 홈: 픽셀 캠퍼스 지도, 장소 선택, 쿠밍이 안내 대화창 | 민원인 |
| `Chat.dc.html` | 민원 접수 채팅 + 접수서(사진, 500byte) + 접수 완료 창 | 민원인 |
| `Activity.dc.html` | 나의 활동: 접수 완료/해결 중/해결 완료 탭, 담당자 채팅, 담당자 답변, 7일 재문의, 성장 게이지 | 민원인 |
| `Decorate.dc.html` | 꾸미기: AI 생성, 전후 비교, 히스토리, 초기화 | 민원인 |
| `AdminDashboard.dc.html` | 직원: 민원 현황, 민원함(필터·검색, [지연]·[재문의] 표시), 부서별 분류, 우선 처리 | 직원 |
| `AdminDetail.dc.html` | 직원: 민원 상세. 접수 경로, 접수 내용/챗봇 기록(접기·폭 조절), AI 요약, 다른 부서로 이관, 상태, 채팅/답변서(접기·폭 조절), 재문의 이력. 상단 '시연용 사례' a~e로 경로별 화면 확인 | 직원 |

핵심 흐름: 민원인이 지도에서 장소 선택 → 채팅으로 접수 → 직원 민원함에 AI 분류된 민원 도착 → 직원이 채팅·처리 후 해결 완료 → 민원인 '나의 활동'에 완료 알림, 성장 게이지 +1.

## 민원 처리 규칙

- 접수 경로 4가지: 챗봇 대화 후 접수 / 챗봇 이관(챗봇이 답 못한 문의) / 접수서 직접 작성 / 꾸미기
- 꾸미기도 민원. 꾸미기 전후 이미지를 첨부해 담당 부서로 일반 민원처럼 전달
- 민원인 신원: 익명 없음. 담당 직원에게 이름 / 학교 메일 / 소속 표시 (2026-10-10 변경, `docs/decisions.md`)
- 직원 배정·상태·이관 규칙은 `docs/decisions.md`의 '민원 배정과 상태'가 기준 (다음 민원 받기, 자동 상태, 넘기는 이유 선택)
- 답하는 방법
  - 채팅: 채팅으로 접수됐거나 직원이 '채팅 활성화'한 민원. 대화가 끝나면 직원이 '대화 종료 후 해결 완료'
  - 답변서: 공식 답변을 작성해 보내면서 해결 완료. 민원인 '나의 활동'에 담당자 답변으로 표시
- 재문의: 해결 완료 후 7일 안에만 가능. 같은 민원 번호를 다시 열어(상태 해결 중 + 재문의 표시) 같은 담당자와 채팅. 7일이 지나면 새 민원으로 접수
- 직원 화면: 상단에 경희대 휘장(`assets/khu_emblem.png`), 오른쪽 하단에 KHU 워드마크(`assets/khu_wordmark.png`)

## .dc.html 파일 읽는 법

브라우저에서 바로 실행되는 파일이 아니라 Claude Design 전용 형식입니다. 구현할 때 **참고용 설계도**로 쓰세요.

- `<helmet><style>`: 공통 CSS (색, 폰트, 버튼 클래스)
- 본문 HTML: 레이아웃과 인라인 스타일이 실제 값 그대로 들어 있음
- `{{이름}}`: 데이터가 들어갈 자리
- `<sc-for>` = 반복, `<sc-if>` = 조건부 표시
- 맨 아래 `class Component extends DCLogic`의 `renderVals()`: 샘플 데이터와 클릭 동작 (React의 state/handler와 같은 역할)

## 디자인 토큰

### 민원인 화면 (픽셀 게임 스타일)
- 폰트: Galmuri11 (`assets/fonts`), 크기 11 / 14 / 16 / 22px 위주
- 이미지는 `image-rendering: pixelated`
- 색
  - 테두리·글자: `#3A2617` (짙은 갈색)
  - 양피지 창: `#F6EBCF` (안쪽 하이라이트 `#FFF7E2`, `#D9C08E`)
  - 나무 명판: `#8A5A33` (밝은 `#B07A48`, 어두운 `#5E3B20`)
  - 주 버튼(벽돌 크림슨): `#B23A2E` (밝은 `#D9644F`, 어두운 `#7E2219`)
  - 보조 버튼(잎 초록): `#6E9A34`
  - 중립 버튼(모래): `#EAD9AE`
  - 상태: 접수 `#3F6370`, 해결 중 `#8C5E1C`, 해결 완료 `#4F7A2A`
- 클래스: `.panel`(창) `.plate`(명판) `.btn` `.btn2` `.btn3`(게임 버튼) `.slot`(입력칸·인벤토리 칸)

### 직원 화면 (사무용)
- 폰트: IBM Plex Sans KR + 숫자는 IBM Plex Mono (Google Fonts)
- 상단바 `#1F2F6B`, 배경 `#F3F4F6`, 카드 흰색 + `1px #D5D9E0` 선, 모서리 3px
- 상태: 접수 `#1F2F6B`, 해결 중 `#8A6416`, 해결 완료 `#2F6B3A`, 지연 `#9E1B24`

## 지도 장소 좌표

`Main.dc.html`의 `raw` 배열: `[번호, 이름, x, y]`, 원본 지도(`campus_map.jpg`, 1122×1402px) 기준 픽셀 좌표입니다.
장소 이름은 지도 그림을 보고 임시로 붙인 것이니 실제 건물명으로 바꿔주세요.
